# Карта площадок Казани — вариант 22

Веб-приложение для поиска площадок Казани по административному району и минимальной вместимости с отображением объектов на интерактивной карте и просмотром предстоящих мероприятий.

## 1. Возможности приложения

Пользователь может:

- выбрать административный район Казани;
- указать минимальную вместимость площадки;
- найти площадки по названию;
- просмотреть найденные площадки в виде списка;
- увидеть площадки на интерактивной карте;
- выбрать площадку и посмотреть её адрес, район, вместимость и координаты;
- просмотреть опубликованные предстоящие мероприятия выбранной площадки.

## 2. Архитектура проекта

Приложение состоит из трёх сервисов Docker Compose:

| Сервис | Технология | Назначение |
|---|---|---|
| `frontend` | Nginx | Раздаёт HTML, CSS и JavaScript, перенаправляет API-запросы |
| `backend` | FastAPI | Готовый сервер из `ghcr.io/nelkor/kazan-events` |
| `db` | PostgreSQL + PostGIS | Хранит данные о площадках и мероприятиях |

Backend в рамках лабораторной работы не разрабатывается. Используется готовый Docker-образ проекта [nelkor/kazan-events](https://github.com/nelkor/kazan-events).

Frontend разработан отдельно для варианта 22. Для отображения карты используется Leaflet и картографические тайлы OpenStreetMap.

```text
PSUTI-DevOps-Lab5/
├── compose.yml
├── README.md
├── frontend/
│   ├── index.html
│   ├── styles.css
│   └── app.js

```

- `frontend/index.html` — структура страницы.
- `frontend/styles.css` — оформление интерфейса.
- `frontend/app.js` — логика карты, фильтров, запросов к API и карточек событий.
- `nginx/default.conf` — конфигурация Nginx и перенаправление запросов к backend.
- `compose.yml` — описание сервисов, сетей, томов и параметров запуска.
- `README.md` — инструкция по установке и использованию приложения.

Исходный код backend загружается из Docker-образа и отдельно в этот проект не копируется.

## 4. Требования

Для запуска необходимы:

- Docker Engine;
- Docker Compose Plugin;
- доступ к интернету для загрузки Docker-образов;
- доступ к интернету в браузере для загрузки картографических тайлов OpenStreetMap и библиотек frontend.

## 5. Запуск приложения

Перейти в корневую папку проекта:

```bash
cd PSUTI-DevOps-Lab5
```

Проверить конфигурацию Docker Compose:

```bash
docker compose config
```

Запустить приложение:

```bash
docker compose up -d
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Все три сервиса должны быть запущены. Для базы данных и backend должна пройти проверка готовности (`healthy`).

Открыть приложение в браузере:

```text
http://localhost:8080
```

При первом запуске Docker загружает необходимые образы, создаёт сеть и том базы данных. Поэтому первый запуск может занять больше времени.

Если на Linux у пользователя нет прав доступа к Docker Engine, команды выполняются с `sudo`, например:

```bash
sudo docker compose up -d
```

## 6. Как работает приложение

1. При открытии страницы frontend получает список административных районов через `GET /api/v1/meta/districts`.
2. Frontend получает метаданные и учебное время набора через `GET /api/v1/meta`.
3. При выборе района и минимальной вместимости frontend отправляет запрос к `GET /api/v1/venues/geojson`.
4. Backend возвращает площадки в формате GeoJSON.
5. Frontend отображает площадки в списке и размещает маркеры на карте.
6. При выборе площадки frontend отправляет запрос к `GET /api/v1/events`.
7. В ответе отображаются опубликованные мероприятия выбранной площадки, начиная с `reference_time`, полученного от backend.

Для отображения маркеров используются только площадки с координатами. Если площадка не имеет координат, она не может быть показана на карте.

## 7. Используемые API-маршруты

| HTTP-метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/v1/meta` | Получение метаданных и `reference_time` |
| GET | `/api/v1/meta/districts` | Получение списка районов |
| GET | `/api/v1/venues/geojson` | Получение площадок для карты |
| GET | `/api/v1/events` | Получение мероприятий выбранной площадки |
| GET | `/health/ready` | Проверка готовности backend |

Пример запроса площадок с фильтрами:

```text
/api/v1/venues/geojson?district_code=VAH&capacity_min=300&has_coordinates=true&limit=1000
```

Параметры:

- `district_code` — код административного района;
- `capacity_min` — минимальная вместимость;
- `has_coordinates=true` — получение площадок с координатами;
- `limit` — максимальное количество результатов.

Пример запроса мероприятий:

```text
/api/v1/events?venue_id=<UUID>&status=published&starts_from=<reference_time>&page=1&page_size=100
```

В запросе используются идентификатор выбранной площадки, статус публикации и нижняя граница даты начала мероприятия.

## 8. Порты и сетевое взаимодействие

| Порт | Сервис | Назначение |
|---|---|---|
| `8080` | Frontend / Nginx | Доступ к приложению из браузера |
| `8000` | Backend | Внутренний HTTP-порт FastAPI |
| `5432` | PostgreSQL | Внутренний порт базы данных |

Наружу публикуется только порт `8080`.

Backend и PostgreSQL доступны внутри общей сети Docker Compose. Frontend отправляет запросы на `/api/v1/...`, а Nginx перенаправляет их на backend по адресу `http://backend:8000`.

## 9. Просмотр логов и проверка работы

Посмотреть состояние сервисов:

```bash
docker compose ps
```

Посмотреть логи всех сервисов:

```bash
docker compose logs --tail=50
```

Следить за логами в реальном времени:

```bash
docker compose logs -f
```

Посмотреть логи backend:

```bash
docker compose logs backend
```

Проверить главную страницу:

```bash
curl -I http://localhost:8080/
```

Проверить готовность backend:

```bash
curl http://localhost:8080/health/ready
```

## 10. Остановка приложения

Остановить контейнеры и удалить созданную Compose-сеть:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в именованном томе `postgres_data`.

Для удаления контейнеров вместе с данными базы данных используется:

```bash
docker compose down -v
```

**Внимание:** параметр `-v` удаляет том базы данных и все сохранённые в нём данные.

## 11. Примечания

- Backend используется в виде готового Docker-образа.
- Конфигурация базы данных задаётся через переменные окружения в `compose.yml`.
- Nginx выполняет роль веб-сервера и обратного прокси (reverse proxy).
- Для загрузки карты и внешних ресурсов требуется интернет-соединение.
- Приложение предназначено для выполнения лабораторной работы № 5, вариант 22.
